### publishers release

Cross-compiles retrovibed's publishplugin programs - `retroapi/publishplugin-activitypub` (installed as
`lemmy.wasm`) and the worked example `retroapi/examples/publishplugin-noop` (`noop.wasm`) - to
`wasip1`/`wasm` and publishes them into the `retropublish` community, tagged
`application/vnd.retrovibed.publish.module` (`retroapi/mimex.RetrovibedPublishModule`).

The filenames matter: a plugin's `.env`, config and cache directories are all derived from the installed
filename (`publishplugin.EnvPath`, `PluginConfigDir`, `PluginCacheDir`), which is what lets several symlinks
to one module hold independent configurations.

Unlike search modules - which `daemons.SearchPluginImport` pulls out of completed
`application/vnd.retrovibed.discovery.search.module` torrents and drops into `search.d` - nothing installs
publisher modules into `publish.d` automatically; `daemons.PublishPluginImport` only reconciles what is
already on disk. So syncing the community gets you the file, and installing it is still manual: upload it
through the console's publishers screen (`POST /c/publishers/`), or build and install from source with
`retrovibe community publisher install`.

#### prerequisites

- The `retropublish` community must already exist:
  `retrovibe community create --name retropublish --mimetype application/vnd.retrovibed.publish.module`
- A retrovibed daemon reachable at `https://host.containers.internal:9998` from the build container (the
  data-plane target for `library import`/`library publish`).
- `RETROVIBED_IDENTITY_SEED` supplied as a secret, e.g. via `--secret=file://./retrovibed-publishers.env`
  (a local `.env`-style file, not committed to the repo, containing `RETROVIBED_IDENTITY_SEED=...`) -- this
  seeds the identity registered against the deeppool cloud service that `community create`/`community info`
  talk to.

#### manual run

```bash
eg compute local --secret=file://./retrovibed-publishers.env --ttl=1h release/publishers
```
